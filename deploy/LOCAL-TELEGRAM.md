# Telegram-бот и Mini App на Mac через ngrok

## Запуск

1. Запустите Docker Desktop. В отдельном терминале запустите туннель:

   ```sh
   ngrok http 8080
   ```

   Оставьте терминал открытым. Скопируйте HTTPS-адрес из `Forwarding`.

2. Перейдите в проект:

   ```sh
   cd ~/Documents/ChatGPT/shlyapoff/ShlyappOff_Shop
   ```

   В существующем `.env` проверьте настройки. Не перезаписывайте файл примером, если в нём уже есть пароли:

   ```dotenv
   TELEGRAM_ENABLED=true
   TELEGRAM_BOT_TOKEN=токен_вашего_бота
   TELEGRAM_ADMIN_CHAT_ID=ваш_числовой_Telegram_ID
   TELEGRAM_BOT_USERNAME=имя_бота_без_знака_собаки
   APP_BASE_URL=https://ваш-адрес.ngrok-free.dev
   ```

   Домен выше — пример. Используйте точный адрес, выданный ngrok, без `/` в конце.
   Сохраните прежние `DB_PASSWORD`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`.

3. Соберите и запустите приложение:

   ```sh
   docker compose up -d --build
   docker compose ps
   curl --fail http://localhost:8080/actuator/health
   ```

   Health должен вернуть `{"status":"UP"}`. Он проверяет приложение и БД; доступность Telegram проверяется отдельно по логам и `/start`.
   Админка: http://localhost:8080/admin.

4. Проверьте публичную сторону туннеля:

   ```sh
   curl --fail --max-time 15 -H 'ngrok-skip-browser-warning: 1' https://ВАШ-ДОМЕН/actuator/health
   ```

5. Откройте личный чат с ботом и отправьте `/start`. Нажмите свежую кнопку «Открыть магазин».
   Бот также устанавливает стандартную кнопку меню «Магазин» на `APP_BASE_URL`.
   Если в BotFather настроена **Main Mini App**, обновите её URL отдельно: это другая настройка Telegram.
   Индивидуальные кнопки меню, ранее настроенные для конкретного чата, могут переопределять стандартную кнопку; свежий `/start` всегда использует текущий адрес приложения.

## Если изменился адрес ngrok

Обновите `APP_BASE_URL` в `.env`, затем пересоздайте только приложение:

```sh
docker compose up -d --force-recreate app
```

Обычный `docker compose restart` не подхватывает новые переменные `.env`.
Отправьте новый `/start`: старые сообщения с кнопками сохраняют старые ссылки.
Обновите URL Main Mini App в BotFather, если используете её.

## Ограничения бесплатного ngrok

ngrok может показать страницу **Visit Site** перед первым открытием HTML. Нажмите кнопку внутри того же окна Telegram, затем при необходимости закройте Mini App и откройте заново.
Это предупреждение ngrok, не ошибка приложения. Заголовок `ngrok-skip-browser-warning` добавлен к API-запросам магазина, но JavaScript не может добавить его к первому открытию страницы, которое выполняет сам Telegram. Параметр в URL или ответный заголовок Spring эту проблему не устраняют.

Если предупреждение не удаётся пройти внутри Telegram, для проверки Mini App потребуется endpoint без такой страницы. Открытие ссылки в отдельном браузере не гарантирует перенос cookie в Telegram.

Документация: https://ngrok.com/docs/pricing-limits/free-plan-limits#removing-the-interstitial-page

## Как отличить ошибки

- **ngrok / ERR_NGROK / не открывается даже health:** проверьте работающий туннель, порт 8080 и Docker.
- **Каталог открыт, но Telegram недоступен:** проверьте загрузку `https://telegram.org/js/telegram-web-app.js` на устройстве. Каталог больше не закрывается бесконечной заглушкой в ожидании SDK. После восстановления соединения используйте «Повторить».
- **Сессия Telegram истекла:** закройте Mini App полностью и заново откройте через бота. Подпись запуска действительна один час; повторная загрузка страницы не выдаёт новую подпись.
- **Telegram не сохраняет сессию:** особенно актуально для Telegram Web при блокировке сторонних cookies. Используйте нативное приложение Telegram или разрешите cookies. Автоматическая перезагрузка в этой ситуации остановлена.
- **Бот молчит:** проверьте `TELEGRAM_ENABLED`, токен и логи. Не запускайте одновременно две копии бота с одним токеном: они конфликтуют за long polling.
- **Профиль недоступен по обычной браузерной ссылке:** это ожидаемо — профиль требует подписанных данных Telegram.

```sh
docker compose logs --tail=150 app
```

Бот подключается после готовности приложения. При неудаче регистрации повторяет подключение каждые 30 секунд; обновление кнопки меню также повторяется без запуска второго polling-сеанса. Уведомления заказов сохраняются в БД и отправляются через outbox. При `TELEGRAM_ENABLED=false` worker не отправляет их; после включения очередь продолжает обработку.

Mac, Docker и туннель должны работать, а Mac — оставаться бодрствующим. Локальный запуск не обеспечивает доступность при выключении или сне компьютера.

## Что проверять после запуска

1. `/start` → магазин → каталог → карточка товара.
2. Добавление товара → корзина → изменение количества → оформление заказа.
3. Закрытие и повторное открытие Mini App: корзина сохраняется за Telegram-аккаунтом.
4. Профиль и подтверждённые заказы.
5. Уведомление администратору о заказе, включая комментарий с символами `<` и `&`.

## Автоматические проверки

Java 21:

```sh
./mvnw test
node --test src/test/js/mini-app.test.cjs
```

Серверные тесты проверяют подпись Telegram, восстановление корзины в новой сессии, оформление, CSRF, настройки cookies и повторное подключение бота. JS-тесты проверяют задержку SDK, таймаут запроса, блокировку cookies, ошибки ngrok, защиту от двойной отправки и снятие заглушки без ожидания внешних ресурсов.

Эти тесты используют H2, MockMvc и имитацию браузерных API. Проверку на реальном телефоне, Telegram API, PostgreSQL и действующем туннеле нужно выполнить отдельно по сценарию выше.
